# 解析記録

## 対象

| ファイル | SHA-256 |
|---|---|
| `Gates32.LZH` | `7E51382CABF586E6F91F1AE2B7FDF17A93CB74869371CBEF5D8B32A438B00733` |
| `gates32.exe` | `44DD83B85AD0A1772E172A2E72BFD42D86BA74AAF0E867A45DB1F296E165FBED` |
| `gates32dc.exe` | `0F03E0E4DEFF66D2597DFB5FCB8DD0AFC05106B4805B20233B768FF0D7750AF2` |

`gates32.exe` はPE32/x86で、DirectDraw、DirectInput、DirectSoundを使用します。`gates32dc.exe` は同じゲーム処理をGDIの `StretchDIBits` で描画する同梱互換版で、現在のWindows上で動的解析するために使用しました。

## DirectX版のヘッドレス実行

`tools/capture_original_trace.py --edition directx` は `gates32.exe` をsuspendedで起動し、次の4か所だけを対象プロセスのメモリ上で一時変更します。ディスク上のEXEは変更しません。

- `0x00401720`: 現在のWindowsでは作れない排他640×400×8 DirectDrawサーフェスを省略
- `0x004016B0`: パレット転送を省略
- `0x00402260`: ゲーム状態へ影響しないDirectSound初期化を省略
- `0x00401CB0`: 表示ラッパーを、原版のソフトウェアフレームバッファ `0x00464008` を渡す未変更のフレームディスパッチャ呼び出しへ置換

これにより入力、乱数、全マネージャ、衝突、得点、リプレイカーソルを含むDirectX版のゲーム処理をそのまま進め、プロセスメモリからフレーム単位の状態を採取できます。DirectX版の可変状態ブロックはDC版より `0xED800` 低いアドレスにあり、採取器は版別のレイアウトを持ちます。

両版は完全には同一ではありません。DirectX版は640×400、DC版は384×400のソフトウェアフレームバッファを持ち、跳ね返るAnime効果のX境界へこの幅を使います。レベル32クリアリプレイではフレーム2857に最初の意味的な差が出ます。type `0x90` の効果がX=383を越えたとき、DC版は反射しますがDirectX版はX=640まで進みます。この差が後続のスロット割り当てと乱数消費へ伝播するため、DirectX版のリプレイ検証にはDirectX版自身を基準とします。

## アーカイブ

`gates32.npk` は先頭が `NishPack`、データ開始位置が0x0Aの16 bit値、0x20から0x20バイト固定長の42スロットを持ちます。各スロットは使用フラグ、相対オフセット、サイズ、20バイト名です。抽出器は `tools/extract_npk.py` にあります。

## 実行時データ

スプライトテーブルはVA `0x0041AED8`、1件0x1Cバイト、最大1536件です。DC版を起動後にプロセスメモリを読み、RLE画像、パレット、描画原点、当たり判定サイズを復元しました。120件が初期化済みでした。

主なスプライト番号は、1=自機、2/3=自機弾、24–29/31–39/42–47=爆発、191–223=紫系32方向弾、225–256=炎系32方向弾、769=Gates、770=Enemy1、771=Enemy2、784–790=Gates変形です。

## オブジェクト

基底オブジェクトは16.16固定小数点の `x/y/vx/vy`、コールバック、境界モード、スプライト、当たり判定、アニメ命令ポインタを持ちます。型はMyShip=`0x100`、Enemy1=`0x200`、Enemy2=`0x201`、Gates1=`0x301`、Gates2=`0x302` です。

更新順は敵、点パーティクル、敵弾、通常アニメ効果、自機、自機弾、ステージ制御です。爆弾は自機の子プールにあり、生成された同じ自機更新内で最初のコールバックを受けます。移植側もこの順番に合わせています。

各マネージャはオブジェクトのコールバック後に絶対右端・下端を `+0x24/+0x26` へキャッシュします。衝突検索は左上を現在座標から、右下をこのキャッシュから読むため、同じプール走査中にGatesの撃破コールバックが座標をずらすと、一時的に非対称な矩形になります。

共有敵スロットは型固有領域を全消去しません。Gates2の追尾角度byte `+0x3C` はイベント1でも残り、後から同じ物理スロットへ生成されたhard Gates2が以前の角度から追尾を再開します。また自機の無敵時間は被弾判定の前に値を検査し、正のときだけ判定を飛ばしてから減算します。残り1のフレームはまだ無敵です。

## 数学と乱数

角度は0–255で一周し、0が右、64が下です。x87で作られたsin/atan表は浮動小数点再計算せず、初期化後データを `runtime-common.bin` から読み込みます。

乱数はMicrosoft Visual C++ 5 CRT互換です。

```text
state = state * 214013 + 2531011
rand  = (state >> 16) & 0x7fff
table[i] = rand - 32768
```

1024要素を生成し、参照前にインデックスを進めます。原版同様、index 1024では直後のゼロのsin要素を1回読みます。

## 得点

表示値は内部値の末尾に0を付けます。加点倍率はレベル、失った残機、デフレーション値から求め、シフト量を最大12に制限します。内部得点が100,000、200,000…へ達するたび残機が増え、デフレーション値へ閾値/100,000を加えます。

クリア条件はレベル>31、残機>23、内部得点>99,999,998のいずれかです。ゲームオーバーは残機<0です。

## NAnime命令VM

`FUN_00405740` は各レコードを `int16 duration, int16 opcode, operands...` として解釈します。移植版は `runtime-common.bin` をVA `0x00416000` に対応させ、次の全命令を汎用インタープリタで実行します。

| opcode | 処理 |
|---:|---|
| `-1` | オブジェクトを破棄 |
| `1` | スプライト番号を設定（`-1`は非表示） |
| `2` | 32 bitイベント番号と32 bit引数をコールバックへ送信 |
| `3` | 指定word数をスキップ |
| `4` | `vx/vy = scale * v >> 8` |
| `5` | 乱数を加えたscaleで速度を変調 |
| `6` | 符号付き剰余を待ち時間へ加算 |
| `0x12` | 16 bitイベントを引数0で送信 |
| `0x13` | `0x10000 + value` を引数0で送信 |
| `0x1000` | スクリプトだけを終了 |

確認済み命令列はGates変形 `0x416488/0x4164A8`、弾消滅 `0x416538`、ボム `0x416598`、軌跡 `0x4165D8`、乱数火花 `0x416640`、爆発 `0x416690`、点滅 `0x4166D0`、自機弾消滅 `0x416708`、銃口 `0x416728` です。durationが0以下なら同じtick内で次命令を続行します。

## 点パーティクルと爆発

点パーティクルは1件0x18バイトの専用プールです。パレット番号15を直接描画し、画面外なら破棄した後、`vy = __ftol(vy - (-6553.6))`、`x += vx`、`y += vy` を実行します。被弾時の8点は乱数角度ごとに原版32 bit sin/cos表を4倍して初速とします。

爆発用コールバックは次の4種を分離して移植しました。

- 軌跡エミッタ: 4tickごとに `0x4165D8` を生成し、親速度を正確に0.9倍
- ランダム爆発: 毎tick、乱数角度と `0x100..0x17f` の大きさで子を生成
- 矩形エミッタ: 4tick中3tick、指定矩形内へランダム爆発を生成
- 放射エミッタ: 乱数開始角から `256/count` ずつ進め、指定数を一度に生成

倍精度定数はEXEの `.rdata`、VA `0x00415058`（`-6553.6`）、`0x00415060`（`5.2`）、`0x00415090`（`0.9`）から直接抽出しました。Gates2モード2の64方向弾は角度の下位2 bitを捨て、`5.2`倍した速度をVC5の `__ftol` で0方向へ切り捨てます。

## 爆弾コールバック

`FUN_00405350` は64件を直接初期化し、角度 `0x4000` から `0x100` ずつ減らします。速度は実行時テーブル `0x004195F0/0x00419670` の16 bit値を20倍し、アニメ列 `0x00416598` を設定します。スプライトポインタは初期化しないため、新規スロットの同フレーム初回コールバックでは衝突を行わず、NAnimeがスプライト31を設定してから移動します。

`LAB_004053E0` は通常アニメと異なり、移動前の現在位置で敵、次に敵弾を検索します。命中時はNAnimeだけを1tick進めて戻り、爆弾自体を消さず、そのフレームは移動しません。未命中時だけ `FUN_004056F0` 相当のアニメ更新・移動・画面外判定を行います。

衝突検索 `FUN_00406670` はスプライト表の `+0x10/+0x14` を右端・下端としてそのまま使います。値0も点または線の当たり判定を意味し、画像幅・高さへフォールバックしません。敵検索側の `FUN_004066E0` は前述のキャッシュ済み絶対右端・下端を使います。

## ランキングと隠しモード

`gates32.sco` は32バイト×10件の固定表です。レコードは `int32 score, time, level, flags; char name[16]` で、`FUN_00408F60` は得点降順、同点は既存項目の後ろへ挿入します。タイトルは内部得点へ末尾0を付け、レベル、時間、クリアフラグを表示します。

F8 `EXPLODE` はAnimeを512件、点パーティクルを512件増やします。F9 `ACCHOH` はWorld共有、Anime、点パーティクルをそれぞれ1024件増やします。通常容量はWorld共有320、Anime 256、自機弾32、点パーティクル128です。
